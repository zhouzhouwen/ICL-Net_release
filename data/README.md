# Data

## Availability

> The dataset is not publicly released due to data confidentiality or usage restrictions. It may be made available upon reasonable request, subject to applicable permissions and agreements.

Requests can be addressed to W. Zhou or to the corresponding author, S. Miwa (The University of Tokyo). No transient data, raw files or excerpts are included in this repository. The released models in `models/` can be used without the dataset (see *Input format* below).

## Dataset

| Item | Description |
| --- | --- |
| Source | 150 steam generator tube rupture (SGTR) transients in SG A of a Japanese four-loop Westinghouse-type PWR, simulated with RELAP/SCDAPSIM/MOD3.4 through the GRAPE platform |
| Design | Full factorial: 3 rupture locations (tube inlet, top, outlet) × 2 core states × 5 isolation delays (1–5 min after reactor trip) × 5 cooldown delays (6–10 min after reactor trip) |
| Signals | 34 Safety Parameter Display System (SPDS) signals, 0–2000 s at 1 s intervals |
| Target | Cumulative primary-to-secondary leakage *M*(*t*), the time integral of the positive break flow; *M*(2000 s) ranges from 27.99 to 40.04 t |
| Folds | 5 outer folds of 30 transients (test fold κ, calibration κ+1, validation κ+2, training κ+3 and κ+4), generated by `make_folds` with seed 20260929 |

Three further transients outside the factorial design are part of the original file set; they are never used for training, calibration or evaluation.

## Layout for authorized users

Place the files as received in `data/raw/`; `scripts/train.py` and `scripts/test.py` read this directory by default (`--data-dir` changes it).

```
data/raw/
├── spds.plt                     labels of the 37 exported variables (34 SPDS signals, 3 break flows)
└── <case_id>.spds.prn           one file per transient (153 files)
```

Each `.spds.prn` file is whitespace-delimited with two header lines followed by 2001 rows (*t* = 0, 1, …, 2000 s) and 38 columns: time, the 34 SPDS signals, and three break-flow channels that define the target and are never used as inputs. Both scripts print the SHA-256 of the dataset and state whether it matches the one used in the paper (`7bcd8cf5…`).

## Input format for new observation windows

`scripts/test.py --input <file.csv>` (and the web demonstrator) accept a long-format CSV with one row per sampled time. Each `sample_id` is one observation window of one transient, observed from the tube rupture (*t* = 0) up to the window length *W*.

| Column | Required | Description |
| --- | --- | --- |
| `sample_id` | yes | Identifier of the observation window |
| `time_s` | yes | Time after the tube rupture in s: 0, 60, …, 60·*W* (at most 21 rows) |
| `window_min` | no | Observation window *W* in min: 5, 8, 10, 11, 12, 13, 14, 15 or 20 (default: last `time_s` / 60) |
| `true_endpoint_kg` | no | Reference *M*(2000 s) in kg, used only to report the error |
| 34 signal columns | yes | Listed below, in physical units; an empty cell marks an unavailable reading |

| No. | Column | Signal | Unit |
| ---: | --- | --- | --- |
| 1 | `neutron_flux_pct` | Power-range neutron flux | % |
| 2 | `reactor_trip` | Reactor trip signal | binary |
| 3 | `si_signal` | Safety-injection actuation signal | binary |
| 4 | `t_cold_a_degc` | Loop A cold-leg temperature | °C |
| 5 | `t_hot_a_degc` | Loop A hot-leg temperature | °C |

| 7 | `t_avg_b_degc` | Loop B average coolant temperature | °C |
| 8 | `t_hot_b_degc` | Loop B hot-leg temperature | °C |
| 9 | `t_cold_b_degc` | Loop B cold-leg temperature | °C |
| 10 | `p_rcs_b_pa` | Loop B primary coolant pressure | Pa |
| 11 | `prv_open` | Pressurizer relief valve opening | fraction |
| 12 | `p_prz_pa` | Pressurizer pressure | Pa |
| 13 | `l_prz_pct` | Pressurizer level | % span |
| 14 | `charging_a_kgs` | Loop A charging flow | kg/s |
| 15 | `charging_b_kgs` | Loop B charging flow | kg/s |
| 16 | `letdown_kgs` | Letdown flow | kg/s |

Format sketch (values are placeholders, not data):

```csv
sample_id,time_s,window_min,neutron_flux_pct,reactor_trip,si_signal,t_cold_a_degc,...,ms_b_kgs
window_01,0,15,<value>,<value>,<value>,<value>,...,<value>
window_01,60,15,<value>,<value>,<value>,,...,<value>
...
window_01,900,15,<value>,<value>,<value>,<value>,...,<value>
```

An unavailable reading is replaced by the last available reading of that channel (or the training mean if none exists) and flagged as unavailable, exactly as in training. ICL-Net then sets every unavailable reading to zero before computing its features, so the filled values do not affect its forecast. The missingness pattern of each window is matched to the 15 sensor conditions of the paper (clean, Drop-1/3/7, G0–G8, Block-7, Outage-7); a matched window receives its calibrated 90 % interval, and any other pattern receives the most conservative calibrated radius for that window.
